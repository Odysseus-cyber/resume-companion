# 表单模板：首次学习，后续本地复用

适用版本：0.3.0 开发预览。模板记录用户已经核对的填写知识，资料值始终从当前简历本地读取。它不是某个企业页面已通过兼容验收的证明。

## 首次保存

1. 使用已保存的简历，在网页展开表单并添加需要的空白经历条目。虚构演示模式不保存模板；测试持久化时请另建虚构测试简历。
2. 点击“识别并填写”。没有适用模板时，AI 启用会显示发送预览；确认后识别和填写。AI 关闭时也可以手动绑定资料并填写。
3. 在网页核对字段含义、对应资料和实际填写结果。卡片勾选“已核对，保存到模板”，再点击“保存已核对字段”。填写成功不等于自动确认，AI 推断也不会自动保存。
4. 可以只保存已核对的部分。资料为空或控件不支持时，仍可核对有效的资料对应关系；没有可靠文字依据或对应有歧义的字段不能保存。
5. 管理页“表单模板”可查看对应字段、改名、停用或删除。删除模板不删除简历或原有手动映射。

## 再次使用与局部学习

再次访问时点击“识别并填写”，插件重新采集当前控件，在本地查找模板：

| 状态                   | 行为                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| 完全适用，且来源为本站 | 直接从当前简历读取资料并填写，不发 AI 请求；空资料或不支持控件仍跳过 |
| 部分适用               | 显示已复用字段与待处理项；启用 AI 时，只预览待识别区域及必要上下文   |
| 暂无适用模板           | 可使用 AI 学习或离线手动绑定                                         |
| 对应有歧义             | 展示原因，用户核对或重新绑定，不强行选取                             |
| 同系统其他站点候选     | 先核对并点击“已核对，确认跨站点复用”，再执行所选字段                 |

关闭 AI 不影响本地模板；开启 AI 也不会为完全适用的本站模板重复请求。部分复用时，确认 AI 发送前可以检查完整请求；“重新学习本页”会重新准备完整页面的发送预览，仍不直接发送。

补齐缺少资料后，插件只从本地读取新值。自定义字段引用限定所属简历，切换简历或删除字段后需要重新核对。网页已有内容始终保留，填写后可撤销，用户后续修改不会被撤销覆盖。

同站点模板更新采用本次结果：保留本次仍匹配的已确认字段，加入新勾选字段，替换已失效的旧对应关系。仅点击重新识别不会删除或改写模板；要保留另一套独立表单配置，应在模板管理中核对当前实例和适用字段。

## 本地保存了什么

模板包含名称、来源 origin、系统标识、启用状态与时间，以及字段含义、脱敏静态文字依据、区域标题、控件类型、资料路径和经历索引。重复经历路径形如 `education.{index}.organization`，本次执行时解析具体索引。

模板不保存资料值、网页已有内容、原始 HTML、完整布局、截图、网址参数、API Key、临时控件编号、脚本或任意选择器。页面文字与区域标题使用本地脱敏流程；不能安全保留的依据不保存为模板。自定义字段内部 ID 和所属简历 ID 只存在本地，不进入 AI 请求。

数据库版本为 3，模板结构版本为 1，最多保存 200 份模板，每份最多 500 个已确认字段。原型、v1 和 v2 数据迁移后增加空模板集合，原资料、映射与设置保持。完整 JSON / 加密备份包含模板；恢复替换当前数据库，清空数据同时删除模板。普通本地库仍不是加密保险箱。

## 结构变化的处理

每次根据当前区域、邻近文字、控件类型和经历分组重新定位，不使用旧控件编号或绝对坐标。区域标题、经历结构或资料对应发生变化时要求核对；手动映射与模板冲突时不静默覆盖。

模板执行允许一种有限的正常重绘：原先为空的原生控件被唯一替代，原父容器和静态文字仍在，类型及结构一致，表单控件数量和区域/经历结构未变化。重新绑定后回读与撤销使用新节点。

以下情况不会强行重新绑定：整行或区域重建、依据文字改变、多个替代控件、替代控件已有内容、控件类型改变，以及填写后自身再次重建。原 AI 布局执行仍严格拒绝被替换的节点。

已支持的原生日期/月控件继续使用通用驱动。自定义日期面板、无明确 ARIA 关系的视觉地区选择器，以及没有验证过的“添加经历”入口仍由用户操作。模板解决对应关系的复用，不自动赋予未知组件可操作能力。

## 验证与后续工作

单元回归位于 `tests/unit/templates.test.ts`、`template-data.test.ts`、`template-rebind.test.ts` 和 `template-management.test.ts`；扩展流程回归位于 `tests/e2e/templates.spec.ts`。测试使用虚构资料和模型响应桩，分别检查首次保存、再次零请求、局部预览、资料变化、模板管理、迁移恢复及隐私。

哈啰和第二家北森页面尚未完成真实模型及实站验收。按 [人工验收](testing.md) 记录模板复用数、AI 新识别数、资料匹配数、实际正确填写数、人工修正数、AI 请求次数和用时，避免把模型响应桩当作实测识别率。
