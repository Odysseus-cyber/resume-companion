# 本地测试与权限排查

1. 在 Chrome 打开 `chrome://extensions`（Edge 使用 `edge://extensions`），加载 `.output/chrome-mv3`（Edge 使用 `.output/edge-mv3`）。已有安装时点击扩展卡片上的重新加载按钮，无需卸载。
2. 运行 `./scripts/dev.sh exec node tests/fixtures/server.mjs`，在安装了扩展的同一个浏览器打开 `http://127.0.0.1:4178/`。Codex 内置浏览器与 Chrome 的扩展环境不同。
3. 在测试页点击工具栏里的 Resume Companion 图标打开侧边栏，选择虚构演示资料，再点击“识别并填写”。测试模板保存时请另建虚构简历，演示模式不持久化模板。
4. 若提示无法读取地址，点击“授权本地测试页并识别”，在浏览器原生权限弹窗中允许 localhost / 127.0.0.1 访问。授权等待期间请先处理浏览器弹窗。
5. 预览后填写，核对结果；手动修改其中一项后撤销，确认手动改动得到保留。

macOS 文件选择器按 `Command + Shift + G` 可直接输入构建目录完整路径；`Command + Shift + .` 切换隐藏文件显示。

## 回归测试范围

`tests/e2e/permissions.spec.ts` 使用未经修改的安装包和全新配置，验证未授权时地址不可见、明确提示与授权按钮、识别操作不会自行新增权限，以及工具栏处理器配置。它不自动接受浏览器原生权限弹窗，也不模拟真实工具栏点击。

`tests/e2e/extension.spec.ts` 使用仅测试用的预授权站点验证识别、填写和撤销等流程。原生授权接受/拒绝及工具栏点击仍需在 Chrome / Edge 按上述流程人工验证。

保留手动演示服务器时可使用另一端口跑自动测试：`RC_TEST_PORT=4179 ./scripts/dev.sh run test:e2e`。

## 可选 AI 识别并填写测试

1. 在资料管理页启用 AI，保存 HTTPS 服务地址、模型和本次会话 Key；回到侧边栏并选择虚构演示资料。
2. 在本地测试页展开表单，点击“识别并填写”。插件先检查本地模板；完全适用的本站模板不会请求 AI。没有模板时，无需先用规则识别或逐项手动绑定即可查看发送预览。
3. 检查请求预览：应有脱敏的页面文字块、控件位置、层级和顺序，以及不含填写值的资料 key 目录。点击“导出脱敏布局”可保存 `resume-companion-layout.json` 检查；不要把真实个人信息或 Key 发到公开问题区。
4. 点击“确认识别并填写”。AI 返回有效匹配后，插件会在本地取值并自动填写；不确定、缺少资料或不支持操作的项会跳过。检查网页实际结果，点击“在网页中定位”核对对应控件，必要时撤销。
5. 请求等待期间修改表单布局或切换资料，确认旧结果不能用于填写。单次超过 500 个候选控件或 200 KB 完整请求正文时应报错，不应静默截断。

演示仍仅限本地页面。AI 失败后不会偷偷改用规则填写；可主动切回离线模式。iframe、Shadow DOM 和未展开区域不在首版布局采集范围；能识别含义的自定义控件仍可能无法自动操作。

若离线模式显示“待识别字段 N”，可点击“在网页中定位”高亮控件；没有可靠标签时，手动绑定仅对本次扫描有效。AI 布局模式会把无标签候选控件连同周围布局一起分析。

请用虚构资料检查实际请求，详见 [AI 与网络验收](testing.md#ai-与网络)。本地拦截响应只能验证流程，不能证明在线模型效果。真实调用使用自选服务，可能产生服务商费用。哈啰页面仍需人工核对，不代表已经通过兼容验收。

## 0.2.1：进度与资料字段

重新加载扩展并刷新招聘页后，在资料管理中可独立录入最高学历、学习形式、户口所在地和民族；留空不会阻止字段名称识别。最高学历不会从教育经历自动推断。旧资料在读取时迁移；当前 0.3.0 保存后写入 v3，增加空模板集合。

侧栏顶部“等待确认发送”表示尚未调用模型。检查预览摘要，可展开“查看完整发送内容”，再点击“确认识别并填写”。“AI 识别中”表示正在请求；超时或错误应显示失败原因与“重新采集并识别”。完成后分别核对候选控件、已识别名称、已匹配资料、已填写数量；匹配到空字段会显示缺少资料。

哈啰页人工验收仍需使用实际在线模型：核对现居住地、最高学历、学习形式、户口所在地、民族的名称、匹配与填写结果；记录仍不支持的控件。若缺失名称，重新采集并在发送前导出脱敏布局，检查文本和控件是否确实包含在请求中。分享前检查静态文字，勿附带真实简历或密钥。

## AI 等待时间（0.2.2）

打开“管理资料 → 数据与设置 → 可选 AI”，在“AI 等待方式”中选择自定义等待时长并输入秒数（例如 120、300），或选择“无限等待”，再点击“保存 AI 设置”。缺省仍为 30 秒。发送预览会展示本次等待策略；识别期间显示已等待时间，并可点击“取消 AI 请求”。取消后不会应用晚到结果。无限等待不保证服务端或网络连接永不中断。

## 动态页面与补充字段（0.2.3）

重新加载扩展并刷新招聘页面。校验提示新增、控件位置移动不应中止整批填写；语义改变或手工修改的控件单独跳过，其他稳定字段继续。模板模式增加了有限的原父容器内空原生控件重绑定，详见 [模板说明](templates.md#结构变化的处理)；整体重建仍需重新采集，不按旧位置强行写入。

AI 先按字段含义寻找已有资料，名称不必逐字相同。有效但未匹配的字段会自动保存为空自定义字段，侧栏出现“补充资料”输入框；输入一次并点击“保存并填写”。不支持操作、已有内容或日期控件仅提供“保存资料”，由你核对网页填写。保存过程不调用 AI；后续识别发送的仍只是字段含义与临时别名，不发送值。重复同名区域、多候选和无有效依据的字段不会自动新建或选择。演示模式不保存新增字段。

## 选择器测试（0.2.4 开发版）

1. 重新加载扩展并刷新测试页。若旧演示服务器仍在运行，用另一端口启动新样例：`RC_TEST_PORT=4180 ./scripts/dev.sh exec node tests/fixtures/server.mjs`，在安装扩展的 Chrome / Edge 打开 `http://127.0.0.1:4180/choices.html`。
2. 新建虚构测试简历，填入最高学历“本科”、户口所在地“浙江省/杭州市/余杭区”和民族“虚构民族”。不要为测试改动自己的正式简历版本。
3. AI 模式核对请求并确认后填写；离线模式也可在预览中手动绑定三个字段到对应资料后填写。学历应显示“大学本科”，地区应选到正确城市下的余杭区，民族应在弹窗操作完成后继续填写。
4. 手工修改民族后撤销：学历和地区应清空，手工修改的民族应保留。地区弹窗展开并有搜索词或已选内容时重新识别，请求预览不应包含弹窗内部内容。
5. 本样例只验证有明确 ARIA 关联的控件。实际哈啰页面如果仍提示不支持，需要取得其脱敏控件结构补充适配，不能把虚构样例通过视为实站验收通过。

## 模板保存与复用（0.3.0 开发预览）

1. 使用已保存的虚构测试简历，打开本地表单。点击“识别并填写”，通过 AI 确认流程或手动绑定建立对应关系，在网页核对结果。
2. 在字段卡片勾选“已核对，保存到模板”，点击“保存已核对字段”。打开“管理资料 → 表单模板”，确认字段、来源与名称；测试改名、停用、启用和删除。
3. 刷新表单清空测试值，再点击“识别并填写”。完全适用时应显示“已使用本地模板填写，未发送 AI 请求”；关闭 AI、重新打开侧栏后重复验证。
4. 改变或增加一个测试字段，确认状态变为部分适用，AI 预览只包含待识别区域及必要上下文，点击确认前不发送。核对新增对应后保存，更新后保留仍匹配字段和新核对字段。
5. 修改区域标题、增删经历或制造同名目标，确认相关字段要求核对。跨站点候选必须先核对确认，不应一识别就直接填写。
6. 导出完整加密备份，停用模板后恢复，确认名称、对应关系、启用状态和简历资料恢复。恢复会替换当前资料和模板，请只在隔离的虚构数据环境测试。

测试结束后在启动服务器的终端按 `Control + C`，关闭本次隔离测试浏览器；不要将测试服务器留在后台。自动回归会自行关闭其创建的 Chromium 环境。
