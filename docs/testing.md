# 人工验收与内测记录

本说明是测试步骤，不是已完成的测试报告。自动化执行结果以本地输出和 CI 为准；真实企业兼容与竞品成绩需要单独验证。

## 首次安装

1. 构建 Chrome / Edge 产物，在独立浏览器资料中加载对应目录。
2. 打开侧边栏和资料管理页，添加两份虚构简历，切换、复制、编辑与删除。
3. 退出并重开浏览器，确认资料保留，AI 仍默认关闭。
4. 在本地测试表单上选择“虚构演示”，确认不会改写个人简历数据库。

## 填写与撤销

测试文本、单选、多选、日期、月份、原生下拉框、ARIA 组件、教育 / 实习 / 项目重复条目及动态插入字段。先识别、核对和选择，再填写；检查网页显示与校验状态。

为一个字段预填旧值，确认保持不变；手动绑定未知字段，重开同站点表单后检查映射复用。填写之后手动修改某项，再撤销，确认用户修改被保留。更换页面后旧计划应失效。不在真实页面提交虚构申请。

## 导入、备份与迁移

- 导入文本型 PDF、DOCX、TXT，核对联系方式，确认原文不自动进入已保存简历。
- 扫描 PDF 应说明无法提取；不支持的文件应显示错误。
- 导出加密备份，恢复并比较简历、映射和设置；错误密码、损坏文件和未知版本应失败且不覆盖原数据。
- 用虚构旧版单 profile 对象测试迁移；测试清空数据后恢复。

## AI 与网络

AI 关闭时录制扩展背景页与扩展页面网络，执行本地保存、导入、识别及填写，确认没有简历或页面数据发送到外部服务。招聘页自身的网络请求另行区分。

配置测试服务与会话 Key，用虚构资料测试以下流程：

1. 启用 AI 后直接点击“AI 识别并填写”，无需先扫描或手动绑定。检查预览中的服务地址、脱敏文字块、控件矩形、父子层级和顺序，以及标准资料 key、中文含义、类型与经历序号。自定义字段必须使用临时别名。
2. 检查实际请求正文：不得包含姓名、电话、学校、经历等简历值、页面已有值、选中内容、可编辑区域内容、隐藏数据、原始 DOM 属性、完整 HTML、截图、页面 URL、自定义字段内部 ID 或 API Key。标准资料 key 可以发送；Key 仅通过鉴权发送。
3. 在静态文字中夹带虚构简历值、页面已有值及常见敏感文本，检查过滤行为。导出布局 JSON 并比较隐私边界。自定义页面文字仍需人工核对，不能以有限样例推断任意页面都不会泄露信息。
4. 点击“确认识别并填写”后，让测试服务返回有效控件、key、判断状态和参考文字编号，确认插件本地取值并自动填写明确匹配项；无需再次逐项勾选。发送确认前不得调用模型或填写。原有内容和敏感字段仍受保护，回读与撤销正常。
5. 返回不确定项、缺少资料、未知编号、重复目标、无效参考文字、错误格式或脚本样式内容，确认对应项不会填写；不支持操作的控件与不确定含义分别显示。
6. 请求等待期间改变布局、输入内容、切换或编辑资料，以及导航后返回，确认旧结果无法继续执行。AI 推断不自动保存为长期映射。
7. 用标签跨多层容器、左右分栏、日期区间、重复经历和无标准标签场景验证布局信息完整；未展开区域、iframe 和 Shadow DOM 不应被宣称已采集。超过 500 个候选控件或 200 KB 完整请求正文时停止并提示缩小范围，不截断数据继续请求。
8. 测试权限拒绝、断网、30 秒超时、HTTP 错误及非法 JSON。失败不得自动回退规则并填写；用户仍可主动使用离线模式。关闭浏览器后确认 Key 消失。备份与日志不得包含 Key。

文件导入只进行本地文本提取与基础解析，页面不应再出现发送简历全文给 AI 的入口。在线模型识别效果需要单独验证；拦截响应只能验证请求边界和交互流程。

## 在线模型与真实页面

自动化响应桩通过后，另用用户配置的在线模型与虚构资料测试语义对应，记录模型名称、日期、场景、识别数、正确填写数和跳过原因。不要把桩响应测试当成模型效果测试。

哈啰招聘页需要用户参与：展开表单后预览或导出无填写值的布局 JSON，核对静态文字已脱敏，再提供复现样本。使用真实申请页面时由用户核对已有草稿，逐项确认填写结果并测试撤销，不提交虚构申请。分别记录“未采集”“未匹配”“已识别但控件不支持”和“填写错误”。取得页面布局样本并验证前，不宣称该页面已修复。
